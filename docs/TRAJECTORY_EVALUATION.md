# Vessel trajectory evaluation

This independent **synthetic event benchmark** complements Scenario Replay and the existing Isolation Forest benchmark. It does not train a new ML model, calibrate the live replay, identify hostile intent, or estimate operational accuracy.

## Data and separation

`coastal_security/trajectory.py` generates two sets of 48 fictional two-hour voyages: 1–8 February 2026 for calibration (seed 91421) and 1–8 March for test (seed 27183). Vessel identifiers, seeds and monitoring dates are disjoint. All locations are invented in an offshore coordinate patch; no client files, vessel identities or Lovable data are used. These are **programmatically generated synthetic data authored with AI assistance**, not real records recovered or inferred by AI.

Each split contains eight voyages in each of six families: steady transit, ordinary speed manoeuvre, benign reporting interruption, injected speed step, corrupted position and injected reporting outage. Labels identify injected data anomalies; benign cases deliberately overlap their magnitudes. Labels are produced from injection causes, independently of detector thresholds. A corrupted fix can generate an outward and return jump: these are one labelled event, not two successful detections.

Both splits share the same families and generation distribution. The holdout tests new vessels, dates and random draws; it is **not an unseen-family or real-world generalisation test**. Periodic reporting, fixed voyage durations, one anomaly per affected voyage and simplified movement are limitations. Weather, vessel class, delayed/reordered messages, spoofing attribution and multi-sensor evidence are not modelled. All four existing Streamlit views and the existing vessel ML benchmark remain available.

## Selection protocol

Twenty-seven candidates combine speed deltas of 6/8/12 kn, implied speeds of 40/60/90 kn and reporting gaps of 10/15/25 minutes. Select only on calibration: maximum event recall under an empirical budget of 0.25 false alerts per vessel-hour; then minimum false alerts; then ascending speed, implied-speed and gap thresholds. Fail if no candidate meets the budget. This illustrative budget is neither a service target nor a confidence bound. Selection rejects the test split. The replay's thresholds are unchanged.

The final report compares calibrated rules, fixed replay threshold values and no-alert baseline on identical held-out cohorts. Thresholds are frozen before test evaluation. Because this is deterministic rule evaluation, there is no estimator-training stage. Future learned models require a third, independent training partition.

## Metric contract

Alerts are sorted chronologically and matched one-to-one to the earliest unmatched ground-truth event with the same vessel and rule. A match must occur at or after onset and within 30 minutes, inclusive. Early, late, cross-rule and cross-vessel alerts do not match. Every unmatched alert is a false alert; a subsequent alert for a previously matched event is additionally labelled a duplicate. This matching protocol is declared in advance and is not a universal maritime standard.

| Measure | Calculation and limits |
| --- | --- |
| Event recall | TP / (TP + FN); undefined without injected positives |
| Alert precision | TP / (TP + FP); undefined with no alerts |
| F1 | 2TP / (2TP + FP + FN); undefined when all terms are zero |
| False alerts / vessel-hour | FP / sum of full monitoring-window hours, including missing reports |
| Missed events | Labelled injections without a matching alert |
| Duplicate alerts | Extra unmatched alerts within the horizon of an already matched injection; included in FP |
| Mean matched delay | Alert time minus onset, averaged over matches only; excludes misses |

No true-negative count, accuracy, ROC-AUC or probability calibration is claimed for this event universe. Scenario filtering changes both the numerator and exposure cohort. Rule filtering keeps all selected vessel-hours. Never sum exposure across rule cuts or average subgroup rates without weighting their denominators. Family filtering uses synthetic labels for analysis only; it is not an operational filtering capability.

## Reproduce

```bash
uv sync --locked
uv run --locked python -m coastal_security.trajectory --output artifacts/trajectory-check
uv run --locked pytest tests/test_trajectory.py
uv run --locked streamlit run dashboard/app.py
```

The output directory must not already exist. `report.json` contains both complete input splits, configuration, 27 calibration candidates, 84 method/family/rule summaries, matching ledgers and missed events. `manifest.json` records the report SHA-256 and generator source SHA-256. The committed `data/trajectory/report.json` must exactly match regenerated bytes. The Streamlit page computes the same report through a deterministic cache and offers the complete JSON with its checksum; display filters do not truncate that download.

## Validation and release

Hand-calculated tests cover event matching, duplicates, horizon boundaries, exposure, undefined metrics, causal cursor behaviour, input order, split isolation, deterministic reproduction and overwrite refusal. Streamlit AppTest and real Chromium checks exercise rendering, filters, tabs, downloads, navigation and narrow layouts. See the current PR's CI results for executed evidence. Local socket restrictions require server/browser checks in CI.

This increment is a reviewable POC. Representative approved data, independent domain review, broader scenario families, uncertainty estimates, operational cost targets and prospective field trials are required before operational claims.
