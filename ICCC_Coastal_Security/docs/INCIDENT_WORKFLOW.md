# Incident Workflow

## 1. Lifecycle
```
C0 Intake ─► C1 Provisional Alert ─► C2 Operator Acknowledged ─┬─► C3 MRCC/MRSC Notified ─┐
   │              │                        │                   ├─► C4 Other Agency Notified┤
   │              │                        │                   └──────────────┬──────────┘
   │              │                        │                                  ▼
   │              │                        └──────────────────────────► C5 Dispatch Confirmed ─► C6 Citizen Safe / Rescued ─► C7 Closed / Referred
   └──────────────┴──────► C8 Unverified / Duplicate / False (reason required, any time before C5)
```
Permitted transitions are enforced in `services/incidents.ALLOWED`; attempts outside them are rejected with the list of allowed moves.

| Transition | Who (permission) | What is recorded | Citizen hears (verified only) |
|---|---|---|---|
| → C0/C1 | Chatbot, alert escalation, any `INCIDENT_CREATE` user | detection time, alert time, source, location + confidence, persons | "Report INC-… registered and sent to the ICCC operator for verification" |
| → C2 | `INCIDENT_VERIFY` (ICCC operator / supervisor / IIC / DSP) | verification time, verifier, owner, `human_verified` | "An ICCC operator has verified your report and is handling it" |
| → C3 | `INCIDENT_VERIFY` (or via MRCC handoff) | MRCC notified time | "Shared with the Maritime Rescue Coordination Centre" |
| → C4 | `INCIDENT_VERIFY` | agency, time | — |
| → C5 | **Automatic** when the tasked field unit reports EN ROUTE on an order issued by a `TASK_ASSETS` officer; or manually by a `TASK_ASSETS` officer when an asset is assigned | dispatch & launch times, confirming field user and authorising officer | "CONFIRMED: a response unit (FIB-…) has been dispatched… ETA ~n min" |
| ON SCENE (order) | field unit | arrival time | "The response unit has reached the reported location" |
| → C6 | `INCIDENT_VERIFY` with outcome text | safe time, outcome | "The response team has confirmed the persons are safe" |
| → C7 | `INCIDENT_CLOSE` (supervisor / IIC / senior) — outcome required | closure time, officer, notes; AAR generated | "Your report has been closed by the authorised officer" |
| → C8 | `INCIDENT_VERIFY` with reason | reason, officer | "Your report could not be verified…" |

Supervisor review is recorded explicitly (button) or automatically at the moment a supervisor issues a tasking order.

## 2. Incident command record
All fields of §29 are captured (see DATA_DICTIONARY.md §5) and shown on the incident's **Record** tab; the **Timeline** tab lists every event
(intake, status changes, citizen updates, tasking, launch, on scene, evidence, notes) with actor and time.

## 3. Sources of incidents
* **Citizen** (AI Maritime Public Assistant) — provisional, with original-language transcript linked.
* **Analytics alert** — "Escalate" on an alert creates an L3 (or L2 for critical) incident classified "POSSIBLE …" linked to the alert and vessel.
* **Manual** — patrol, telephone, VHF reports (Incident Command › New incident).
* **Exercise scenarios** — flagged EXERCISE.

## 4. Evidence
* Upload photos, video, voice, screenshots, UAV imagery or CCTV references against the incident; citizens' photos/voice attach automatically.
* **Preserve track logs** writes the vessel track and asset state for the incident window to a JSON file, hashes it and seals it.
* Each item stores capture time vs upload time, officer, SHA-256, custody status and an append-only custody log; **Verify** recomputes the hash.

## 5. After-Action Review (auto-generated at C7, draft visible before)
* Timeline; response intervals: detection→alert, alert→verification, verification→dispatch, dispatch→launch, launch→arrival, alert→arrival, total.
* Resources used, with the authorising officer and the asset's rank in the stored AI recommendation.
* Evidence list with hashes and custody state.
* Improvement points generated by rules, e.g. verification > 5 min, decision-to-dispatch > 10 min, a lower-ranked asset chosen (reason to be recorded),
  UNABLE responses (readiness data accuracy), approximate initial location (promote live-location / NABHMITRA use), no evidence preserved,
  non-English report (native-speaker check of the transcript).
* Labelled as an auto-generated draft for the closing officer's review.

## 6. Queues & views (Incident Command menu)
Active Alerts · Incidents · Verification Queue (C0/C1) · Tasking (verified, no asset) · Dispatch / Response Tracking (asset assigned; order
timelines) · Search and Rescue (distress families) · Evidence · Closure (C5–C8) · After-Action Review (C7).
